# 微信视频号关注账号更新监控脚本开发计划

## 1. 项目目标

开发一个 AutoJs6 脚本，从微信视频号「我的关注」列表开始遍历关注账号，进入账号主页的「剧集」栏，直接在剧集栏页面 OCR 读取剧集名称，并把账号名称、剧集名称、读取时的北京时间输出到 CSV。

当前开发边界：脚本主入口从已经打开的「我的关注」列表开始。微信主页、发现页、视频号首页、个人中心到「我的关注」的前置导航暂时不作为主线，只保留为可选辅助脚本。

目标数据字段：

- 账号名称
- 剧集名称
- 读取北京时间

默认输出文件：

```text
/sdcard/Download/wechat_video_watch.csv
```

当前不读取页面发布时间，也不按发布时间窗口筛选。每轮每个账号最多读取 12 部剧；CSV 写入前按 `账号名称 + 剧集名称` 去重。

## 2. 当前已确认需求

1. 采集入口是视频号个人页中的「我的关注」账号列表，不采集视频号首页顶部的关注信息流。
2. 当前要求手动停在「我的关注」列表后运行主控脚本，先把列表之后的逻辑做稳定。
3. 微信视频号界面对无障碍树读取有防护，不能依赖无障碍节点作为主要信息来源。
4. 不读取页面发布时间；写入 CSV 的时间为脚本读取成功时的北京时间。
5. 每个账号每轮最多读取 12 部剧。
6. 第一遍运行用于初始化 CSV 并写入读取到的剧集；后续运行继续读取 12 部，但同账号同剧名已存在则跳过。
7. 输出格式使用 CSV，要求清晰、可直接查看。
8. 后续真实使用大约 20 个剧场账号。

## 3. 技术路线

脚本改为“截图 OCR + 坐标点击”为主、无障碍树辅助的路线。

说明：微信视频号部分页面可能隐藏、裁剪或弱化无障碍节点，不能假设无障碍树一定完整。但前期开发仍应优先探测无障碍树，因为它能帮助确认页面状态、按钮位置、列表结构和可点击父节点；只有节点缺失、文本不可读或点击失败时，才降级到截图、OCR、ROI 和坐标点击。

核心手段：

- 无障碍树探测：读取当前页面节点，保存 `text`、`desc`、`id`、`className`、`bounds`、`clickable`、`scrollable`、`visibleToUser` 等信息。
- 节点选择器：优先使用 `idMatches()`、`textMatches()`、`descMatches()`、`className()`、`visibleToUser(true)` 定位稳定控件。
- 节点回溯点击：命中文本节点后，向上查找第一个 `clickable()` 父节点执行点击；控件点击失败时，用节点 `bounds()` 中心坐标模拟点击。
- 版本控件表：参考微信清粉项目，为不同微信版本维护控件 id 映射，避免把 `com.tencent.mm:id/...` 分散硬编码在业务逻辑里。
- 截图：使用 `captureScreen()` 获取当前屏幕。
- OCR：识别截图中的文字块、坐标框和置信度。
- ROI 裁剪：针对关注列表、账号主页、视频详情页设置相对屏幕区域，只识别关键区域。
- 坐标点击：根据 OCR 文字框、固定区域和相对坐标执行点击。
- 模板匹配：对稳定图标或按钮截图做图片匹配兜底，例如返回、个人入口、关注入口。
- 白名单：目标账号使用白名单，降低 OCR 误识别带来的误点风险。
- 截图留痕：失败或低置信度时保存截图、OCR JSON 和日志，方便人工复盘。

整体策略：

1. 先用探测脚本采集关键页面的无障碍树、截图、OCR 结果，判断每个页面适合使用节点、OCR 还是混合方式。
2. 当前不再把自动进入「我的关注」列表作为主线；主控脚本默认假设已经停在「我的关注」列表。
3. 在「我的关注」列表中优先截图并 OCR，识别账号名称和账号条目位置；可用的无障碍 bounds 只作为辅助信号。
4. 只点击白名单账号，避免误入无关账号。
5. 进入账号主页后，先 OCR 识别顶部 `主页 / 视频 / 剧集` 三个 Tab，点击 `剧集` 进入剧集页。
6. 在剧集栏页面按从上到下、从左到右 OCR 识别可见剧集名称。
7. 当前主线不点击剧集卡片进入详情页。
8. 读取成功时生成当前北京时间。
9. 按 `账号名称 + 剧集名称` 检查 CSV，已存在则跳过，不存在则写入。
10. 返回账号主页剧集页继续检查下一个剧集。
11. 当前账号读取 12 部剧或连续无可读剧集后，返回关注列表检查下一个账号。

## 4. OCR 识别设计原则

### 4.1 坐标使用方式

所有坐标优先使用屏幕宽高比例，不写死单一机型绝对坐标。

示例：

```javascript
const x = Math.round(device.width * 0.88);
const y = Math.round(device.height * 0.92);
click(x, y);
```

对确实稳定的入口，可在 `config.js` 中保留设备配置。

### 4.2 OCR 区域划分

推荐先按页面建立 ROI：

- 关注列表：中部列表区域，排除顶部导航和底部栏。
- 账号主页：顶部账号名区域、`主页 / 视频 / 剧集` Tab 区域、剧集卡片区域。
- 账号主页剧集栏：剧集卡片标题区域。
- 导航按钮：顶部左右角、底部 tab 区域。

优先裁剪 ROI 后 OCR，减少无关文字干扰，提高速度和准确率。

### 4.3 账号点击策略

关注列表中只处理白名单账号。

匹配流程：

1. OCR 当前屏幕。
2. 在 OCR 文本块中查找白名单账号名，允许轻微 OCR 差异。
3. 命中后点击文本块中心或该行条目中心。
4. 如果未命中，滚动关注列表继续查找。
5. 如果多次未命中，记录缺失账号并继续下一个。

### 4.4 视频详情页文本识别

账号主页剧集栏不强依赖节点。无障碍树如果能暴露卡片 bounds 或列表容器，可以用于辅助判断页面状态和下滑；当前主线直接在剧集栏页面 OCR 读取可见剧名。

识别流程：

1. 截取账号主页剧集栏可见区域。
2. OCR 读取可见文字行。
3. 过滤 `主页 / 视频 / 剧集 / xx集 / 已关注 / 私信` 等干扰文本。
4. 按从上到下、从左到右排序候选剧名。
5. 记录读取成功时的北京时间。

### 4.5 无障碍树探测设计

V1 阶段先建立 `probe_accessibility_tree.js`，用于在人工打开目标页面后保存当前页面的节点树。建议每个节点输出：

- `text`：节点文本。
- `desc`：节点内容描述。
- `id`：控件完整 id，例如 `com.tencent.mm:id/...`。
- `className`：控件类型，例如 `android.widget.TextView`、`androidx.recyclerview.widget.RecyclerView`。
- `bounds`：节点屏幕范围，用于点击或 ROI 对齐。
- `clickable`、`scrollable`、`enabled`、`visibleToUser`：节点能力和状态。
- `depth`、`index`、`childCount`：用于还原树结构。

探测脚本应同时记录：

- `currentPackage()` 和 `currentActivity()`。
- 微信版本号和安装来源。
- 当前页面截图。
- OCR 结果。
- 原始无障碍树 JSON。

通过这些结果判断每个页面的策略：

- 节点文本完整：优先用节点定位和点击。
- 节点无文本但 bounds 稳定：节点提供坐标，OCR 提供文字。
- 节点树缺失或主要内容在不可读区域：使用截图、OCR、ROI 和模板匹配。
- 列表节点可滚动：优先 `scrollForward()`；失败再使用 `swipe()`。

### 4.6 Auto.js / AutoJs6 可用能力

本项目可用到的 Auto.js 能力：

- 无障碍选择器：`id()`、`idMatches()`、`text()`、`textMatches()`、`desc()`、`descMatches()`、`className()`、`visibleToUser(true)`。
- 节点读取：`node.text()`、`node.desc()`、`node.id()`、`node.className()`、`node.bounds()`、`node.parent()`、`node.children()`。
- 节点操作：`node.click()`、`node.scrollForward()`、`node.setText()`。
- 坐标操作：`click(x, y)`、`swipe(x1, y1, x2, y2, duration)`、`setScreenMetrics(width, height)`。
- 应用状态：`launch(packageName)`、`waitForPackage(packageName)`、`currentPackage()`、`currentActivity()`、`back()`。
- 截图与图像：`requestScreenCapture()`、`captureScreen()`、`images.clip()`、`images.findImage()`。
- 文件留痕：`files.write()`、`files.append()`、`files.ensureDir()`。
- 稳定性：`device.keepScreenDim()`、`threads.start()`、`events.observeKey()`，可用音量键作为紧急停止。

推荐操作方式：

1. 在手机安装 AutoJs6，并开启无障碍权限、悬浮窗权限、截图权限。
2. 手动打开微信视频号目标页面。
3. 先运行 `probe_accessibility_tree.js`，保存无障碍树、截图和 OCR。
4. 如果 AutoJs6 自带布局分析可用，打开“布局分析/布局层次分析”，手工查看关键控件的 `fullId`、`text`、`desc` 和 `bounds`。
5. 将稳定控件 id 写入 `config.js` 或后续的微信版本 id 映射文件。
6. 再运行正式采集脚本，让脚本优先尝试节点定位；节点失败时自动降级到 OCR 和坐标。

## 5. 阶段开发计划

### 阶段 V1：无障碍树 + 屏幕视觉双探测

目标：确认微信视频号关键页面能否通过无障碍树读取页面结构、按钮、列表和可点击区域；同时通过截图和 OCR 读取必要文本，并确定各页面 ROI。

覆盖页面：

- 发现页
- 视频号首页
- 视频号个人页
- 我的关注列表
- 账号主页
- 视频详情页

产物：

```text
probe_accessibility_tree.js
probe_screen.js
```

脚本能力：

- 检查 AutoJs6 无障碍服务是否开启，未开启时提示进入系统设置。
- 保存当前页面无障碍树 JSON。
- 输出节点文本、描述、控件 id、className、bounds、clickable、scrollable、visibleToUser。
- 保存当前包名、Activity、微信版本等运行环境信息。
- 请求并验证截图权限。
- 保存当前整屏截图。
- 按预设 ROI 保存裁剪截图。
- 对整屏和 ROI 执行 OCR。
- 输出 OCR 文本、坐标框、置信度。
- 保存探测结果到本地 JSON/TXT 文件。

推荐输出目录：

```text
/sdcard/Download/wechat_video_probe/
```

验证步骤：

1. 手动打开微信「发现」页，运行探测脚本。
2. 手动打开视频号首页，运行探测脚本。
3. 手动打开视频号个人页，运行探测脚本。
4. 手动打开「我的关注」列表，运行探测脚本。
5. 手动打开任意账号主页，运行探测脚本。
6. 手动点进任意视频详情页，运行探测脚本。
7. 检查输出中是否能看到账号名、剧名文本及其坐标框。
8. 检查无障碍树中是否能看到「发现」「视频号」「关注」「返回」「账号名」「列表容器」等关键节点。
9. 记录每个页面最终推荐策略：节点优先、节点+OCR 混合、OCR/坐标兜底。

通过标准：

- 输出中包含当前页面的无障碍树 JSON，且节点字段足以用于后续分析。
- 能识别哪些页面节点可用，哪些页面节点不可用或不稳定。
- 可点击节点能通过回溯父节点或 bounds 中心坐标定位。
- 关注列表截图 OCR 能识别目标账号名称，或能确定账号条目的可点击坐标。
- 账号主页剧集栏 OCR 能识别可见剧名。
- 视频详情页左下 ROI 能识别标题/文案主体。
- OCR 输出中包含坐标框，能够转换为点击点或裁剪区域。

未通过处理：

- 如果无障碍树为空或内容明显缺失，标记该页面为 OCR/坐标主导。
- 如果节点有 bounds 但无文本，尝试用节点 bounds 对齐 OCR 文本块。
- 如果微信版本更新导致控件 id 变化，使用 Auto.js 布局分析重新标定 fullId。
- 如果整屏 OCR 干扰过大，缩小 ROI。
- 如果剧集栏剧名无法识别，尝试提高截图清晰度、改变裁剪区域或增加 OCR 引擎。
- 如果账号名误识别严重，改为白名单别名表、截图模板或人工固定排序方案。

V1 探测仅作为截图、ROI、OCR 权限和坐标校准工具，不再作为主流程阻塞项。主流程确认走“截图 OCR + 坐标点击”。

### 阶段 V2：免费剧集弹窗剧名采集（备用）

目标：备用验证工具。在已经打开视频详情页的情况下，点击左下“免费剧集”入口，打开剧集面板，并稳定识别面板里的大号剧名。当前阶段 1 主线不使用这个入口。

产物：

```text
src/collectors/collect_current_series.js
```

脚本能力：

- 截取视频详情页左下“免费剧集”入口 ROI。
- 优先通过 OCR 命中“免费剧集”文字框并点击中心。
- OCR 未命中时，使用 `series.fallbackClickRatio` 备用相对坐标点击。
- 等待剧集面板弹出。
- 截取 `series_panel_title` ROI，识别面板大号剧名。
- 追加写入剧名 CSV。
- 保存点击前截图、点击后面板截图、入口 ROI、剧名 ROI、OCR JSON 和 summary。

验证步骤：

1. 手动打开一个能看到“免费剧集：xxx 全xx集”的视频详情页。
2. 运行 `src/collectors/collect_current_series.js`。
3. 检查脚本是否点击“免费剧集”入口并弹出剧集面板。
4. 检查 `roi_free_series_entry.png` 是否裁到入口条。
5. 检查 `roi_series_panel_title.png` 是否裁到弹窗大号剧名。
6. 检查 `summary.txt` 中的剧名是否与人工看到的一致。
7. 重复运行同一视频，检查 CSV 是否不会明显重复。

通过标准：

- 能稳定点击“免费剧集”入口。
- 能稳定弹出剧集面板。
- 能从大号字体中识别剧名，例如 `三千万项目后，她成了总裁`。
- CSV 字段清晰可读。
- 失败时能留下截图和 OCR 日志。

只有 V2 通过后，进入 V3。

### 阶段 V3：单账号主页剧集页采集

目标：从一个账号主页开始，OCR 识别 `主页 / 视频 / 剧集` 三个 Tab，点击 `剧集`，再自动检查该账号剧集页里的剧集卡片。

产物：

```text
collect_one_account.js
```

脚本能力：

- 通过 OCR 或配置读取当前账号名称。
- OCR 识别账号主页 Tab：`主页`、`视频`、`剧集`。
- 点击 `剧集` Tab，进入如截图所示的剧集卡片页。
- 按从上到下、从左到右直接 OCR 剧集栏卡片标题。
- 读取成功后直接写入 `账号,剧名,读取北京时间`，不进入详情页。
- 返回账号主页。
- 继续点击下一个剧集卡片。
- 遇到连续重复剧名或无法识别剧名时停止或跳过。
- 支持一个账号主页中多个剧集逐个打开并记录剧名。

验证步骤：

1. 手动打开示例账号主页，例如「幸运剧场16888」。
2. 运行脚本。
3. 检查是否 OCR 识别出 `主页 / 视频 / 剧集`，并点击 `剧集` Tab。
4. 检查是否点击第 1 个剧集卡片并记录剧名。
5. 返回账号主页的剧集页后继续检查第 2 个剧集卡片。
6. 遇到重复剧名或无法识别剧名时按配置停止或跳过。
7. 检查 CSV 中是否包含该账号最近剧集对应的剧名。
8. 重复运行该账号，检查去重效果。

通过标准：

- 能稳定从账号主页进入剧集页/详情页。
- 能稳定返回账号主页。
- 能稳定识别并点击 `剧集` Tab。
- 能按照从新到旧顺序检查多个剧集卡片。
- 能在连续重复或连续识别失败后停止，不无限下滑。
- CSV 数据和人工观察一致。

只有 V3 通过后，进入 V4。

### 阶段 V4：关注列表 OCR 遍历

目标：从「我的关注」列表开始，遍历全部目标账号并执行单账号采集。

产物：

```text
collect_following_accounts.js
```

脚本能力：

- 截图并 OCR「我的关注」列表。
- 在 OCR 结果中匹配账号白名单。
- 点击匹配账号进入主页。
- 执行 V3 单账号采集。
- 返回关注列表。
- 继续下一个账号。
- 支持滚动加载更多账号。
- 支持最多账号数限制，默认 30。
- 记录未找到、识别失败、疑似误识别的账号。

推荐配置：

```javascript
const TARGET_ACCOUNTS = [
    // 后续填写 20 个剧场账号名称
];

const ACCOUNT_ALIASES = {
    // OCR 常见误识别别名，例如：
    // "幸运剧场16888": ["幸运剧场l6888", "幸运剧场168B8"]
};
```

验证步骤：

1. 手动打开「我的关注」列表。
2. 配置 2 到 3 个测试账号白名单。
3. 运行脚本。
4. 检查脚本是否只进入白名单账号。

6. 检查脚本是否能回到关注列表并继续下一个账号。

通过标准：

- 能遍历多个账号，不跳错、不重复、不卡死。
- 白名单账号能全部检查。
- 非白名单账号不会误采。
- OCR 误识别能通过别名表或人工配置修正。
- CSV 内容和人工抽查结果一致。

## 6. 时间判断规则

默认命中规则：

- `刚刚`：命中
- `x分钟前`：x <= 180 命中
- `x小时前`：x <= 3 命中
- `今天 HH:mm`：按当前时间计算，差值 <= 180 分钟命中

默认停止规则：

- 发现 `4小时前` 或更早，停止当前账号。
- 发现 `昨天`、具体日期，停止当前账号。
- 连续多次无法在剧集栏识别新剧名，停止当前账号并记录备注。

说明：

当前不按发布时间窗口筛选。最终 CSV 通过账号名和剧名去重，人看到的是新增剧集记录。

## 7. CSV 去重策略

默认去重键：

```text
账号名 + 剧名
```

后续如果能读取更稳定的视频唯一信息，可升级为：

```text
账号名 + 视频标题 + 视频详情截图指纹
```

截图指纹可以使用视频详情页关键 ROI 的哈希值，作为 OCR 不稳定时的辅助去重信息。

## 8. 风险与兜底方案

### 风险 1：OCR 无法稳定识别标题或时间

处理：

- 缩小或调整 ROI。
- 保存高清截图用于人工分析。
- 增加 OCR 引擎或切换识别参数。
- 对常见时间文本增加容错，例如 `分钟前` 被识别成 `分鈡前`。

### 风险 2：微信视频号页面结构变化

处理：

- 坐标使用屏幕比例。
- 关键按钮使用模板匹配兜底。
- 页面探测脚本长期保留，方便重新标定 ROI。

### 风险 3：账号主页视频排列或加载不稳定

处理：

- 每次进入账号主页后等待加载。
- 优先点击首屏最新剧集卡片。
- 返回后通过固定网格坐标定位下一个剧集卡片。
- 对每个账号设置最大检查视频数，避免死循环。

### 风险 4：定时运行时微信状态异常

处理：

- 脚本启动先尝试返回稳定入口。
- 超时后截图/记录日志并停止，不做危险点击。

### 风险 5：OCR 误识别导致误点账号

处理：

- 强制白名单。
- 使用账号别名表。
- 点击前二次确认当前行附近是否有匹配文本。
- 对低置信度匹配只记录，不点击。

### 11.2 决策边界

OCR 结果只作为候选信号，不直接拥有执行权。脚本必须校验：

1. OCR 文本必须经过白名单、关键字或规则筛选。
2. 点击坐标优先使用 OCR 框中心或经过校准的屏幕比例坐标。
3. OCR 置信度过低、位置不在预期 ROI、文本命中不明确时，不执行点击。
4. 对发布、私信、评论、购买、删除、付款、授权、登录确认等高风险按钮，脚本必须保持保守。

### 11.3 当前开发顺序

1. 主入口固定为 `src/master_collect.js`，前置条件是已经手动停在「我的关注」列表。
2. 阶段 1：单账号链路验证。截图/OCR 识别账号行坐标 -> 点击账号主页 -> OCR 点击 `剧集` Tab -> 直接 OCR 剧集栏可见剧名 -> 下滑继续 -> 写入 `账号,剧名,读取北京时间`，最多 12 部。
3. 阶段 2：关注列表多账号遍历。阶段 1 验证完成后，再扩大到多个关注账号。
4. 阶段 3：CSV 长表性能优化。当前先用线性扫描去重，后续再处理 CSV 越来越长导致的查询效率问题。
5. 任意入口自动导航延期，不参与当前验收。

优先级上，先保证“看得准”和“点得准”，再扩大自动化范围。每个新点击动作都先 dry-run 保存证据，确认多次稳定后再开启真实点击。
